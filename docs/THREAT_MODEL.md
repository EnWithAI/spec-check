# Threat model

Assets: the user's machine and CI runner, secrets that may appear in spec text, the integrity of review output
(Markdown summaries and PR artifacts), and the trust reviewers place in the report.

| Threat                                                                                         | Mitigation                                                                                                                                                                      | Test                              |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| Spec text instructs the tool or a downstream AI reviewer ("ignore previous instructions…")     | Spec text is data; only documented front-matter keys and suppression comments change behavior, and both are reported. The Markdown report starts with an untrusted-data notice. | `rendering.test.ts` (S9)          |
| Markdown/HTML injection into job summaries (scripts, images, links, `@mentions` pinging teams) | Excerpts and paths are code spans; free text escaped; `@` neutralized; control/bidi characters made visible                                                                     | `rendering.test.ts`               |
| Secrets pasted into a spec leak via excerpts                                                   | Token-pattern redaction (GitHub, AWS, Slack, OpenAI/Anthropic, Google, npm, Stripe, JWT, private keys, URL credentials); `--no-excerpts`                                        | `rendering.test.ts`               |
| Code execution                                                                                 | No `child_process`, `vm`, `eval`, dynamic `import()` or network modules in `src/` (lint + static test). Config is JSON only. Gherkin/`accept` blocks are never run.             | `security.test.ts`                |
| Path tricks (symlinks to `/etc`, `..` in Action inputs)                                        | `lstat`, symlinks never followed; Action rejects absolute and `..` paths                                                                                                        | `acceptance` S9, `action.test.ts` |
| Resource exhaustion (huge or many files, many findings)                                        | 2 MiB/file, 1,000 files, 5,000 findings, directory depth 20, Markdown report ≤ 60k chars, each reported                                                                         | `units.test.ts`                   |
| Binary/non-UTF-8 input                                                                         | Strict UTF-8 decoding; NUL check; skipped with limitation                                                                                                                       | `units.test.ts`, S9               |
| Regex denial of service                                                                        | No user-supplied regex; built-in patterns are linear or bounded (`{3,80}`)                                                                                                      | review                            |
| Gaming the policy via suppressions or config                                                   | Suppressions listed in the report; config changes visible in PR diff; CODEOWNERS guidance                                                                                       | `docs/CONFIG.md`                  |
| Over-trust ("Spec Check passed, so the spec is good")                                          | `not-checked` limitation in every report; hypotheses labelled; no score                                                                                                         | acceptance                        |
| Trojan Source in this repository                                                               | Test rejects bidi/invisible characters in `src/` and `test/`                                                                                                                    | `security.test.ts`                |
| Action privilege misuse                                                                        | `pull_request` + `contents: read`; env-passed inputs; no tokens used                                                                                                            | `action.test.ts`                  |

Residual risks: the word lists will produce false positives and negatives; Markdown outside the subset may be
mis-parsed (reported as `markdown-subset`); redaction is pattern-based and cannot catch every secret.
